# LearnJapanese — N5→N1 course app (implementation plan)

**Outcome:** a Next.js 16 app that teaches Japanese from N5 through N1: a sequential grammar curriculum with complete, concise notes; vocabulary injected unit-by-unit from real JLPT word lists; kanji with stroke-order data; spaced-repetition review; in-app practice; the full JMdict dictionary; quizzes exportable in quiz-renderer's exact format; Better Auth + Prisma/MySQL. Kana is assumed known (no kana lessons; a reference chart page is included). All five levels get fully authored content at max detail — the app is built first, then content is authored level-by-level (N5 → N4 → N3 → N2 → N1) without stopping.

## 3. Data sources (verified 2026-09-07) & import pipeline
Fetched by `scripts/data/fetch.mjs` into `data/raw/` (gitignored); imported by `scripts/data/import-*.ts` (tsx, streamed, 1000-row batched inserts):
1. **Vocabulary** — jmdict-simplified release JSON (`https://github.com/scriptin/jmdict-simplified/releases/download/{tag}/jmdict-eng-{tag}.json.zip`, latest 3.6.2+, 11 MB zip → 118 MB JSON; **218,726 entries / 253,512 senses**; shape `{id(ent_seq), kanji[{text,common}], kana[{text,appliesToKanji}], sense[{partOfSpeech[],gloss[]}]}`). Romaji generated from kana at import via wanakana.
2. **JLPT levels** — `stephenmk/yomitan-jlpt-vocab` `original_data/n1..n5.csv` (CC BY-SA 4.0, rows keyed by `jmdict_seq`: N5 685, N4 641, N3 1731, N2 1813, N1 3428 = **8,298 words**) → `Word.jlptLevel`.
3. **Kanji** — `kanjidic2.xml.gz` from `https://www.edrdg.org/pub/Nihongo/` (1.5 MB gz, **13,108 kanji**): literal, grade, stroke_count, ja_on/ja_kun readings, EN meanings. (Its `jlpt` field is stale pre-2010 — kanji levels are assigned by curriculum instead.)
4. **Stroke order** — KanjiVG `r20250816` main zip (12.6 MB, 11,661 SVGs, CC BY-SA 3.0) → converted per-kanji to ordered stroke-path JSON → `Kanji.strokeData` (drives a stroke-animation player).
5. **Example sentences** — Tatoeba per-language exports (`downloads.tatoeba.org/exports/per_language/jpn/`: `jpn_sentences_detailed.tsv.bz2` **248,896 JP sentences**, `jpn-eng_links.tsv.bz2` **280,660 JP↔EN pairs**, CC BY 2.0 FR) → `Sentence` table.
- **Search:** MySQL `FULLTEXT ... WITH PARSER ngram` index (raw-SQL migration) over jp+kana+romaji+glosses; runtime detection with LIKE fallback if ngram is unavailable on the server.
- **Licensing:** `/about/sources` page displays the EDRDG attribution sentence ("This package uses the JMdict/EDICT and KANJIDIC dictionary files. These files are the property of the Electronic Dictionary Research and Development Group, and are used in conformance with the Group's licence."), plus Tatoeba CC BY 2.0 FR, KanjiVG CC BY-SA 3.0, and tanos.co.uk/Jonathan Waller CC BY credits. README documents the EDRDG monthly-refresh condition with an `npm run data:update` script.

## 4. Prisma schema (provider mysql) — key models
- **Better Auth managed:** User, Session, Account, Verification.
- **UserSettings**(userId @unique; `scriptMode: FURIGANA|HIRAGANA|ROMAJI` default FURIGANA; `furiganaMode: ALWAYS|HOVER|OFF`; `audioOn` default true; `dailyGoalXp` default 20; `freeNav` default false)
- **Unit**(id slug, level "N5".."N1", order, title, titleJp, description) @@unique(level, order)
- **Lesson**(id slug, unitId, order, title, titleJp, grammarLabel e.g. "〜てください", summary, body Json — structured sections: meaning / formationRows[{pattern,note}] / usage[] / register / pitfalls[] / related[]) @@unique(unitId, order)
- **Example**(lessonId, order, jp, kana, romaji, en, segments Json[{base,reading}]) — hand-authored, readings verified
- **Word**(id String = ent_seq, common Bool, jlptLevel Int?, kanjiForms Json, kanaForms Json, romaji String, senses Json[{pos[],glosses[]}], searchText) + ngram FULLTEXT
- **UnitVocab**(unitId, wordId, order) — the curated teaching subset; all 8,298 JLPT words allocated across units
- **Kanji**(char @id, level, grade, strokeCount, onyomi Json, kunyomi Json, meanings Json, strokeData Json, unitId, mnemonic)
- **QuizItem**(id, scope LESSON_PRACTICE|UNIT_EXAM|REVIEW, lessonId?, unitId?, order, type, payload Json — quiz-renderer question shape 1:1, points, tags)
- **LessonProgress**(userId, lessonId, status, bestScore, attempts, completedAt) @@unique(userId, lessonId)
- **ExamAttempt**(userId, unitId?, levelExamFor?, score, responses Json, passed, createdAt)
- **SrsCard**(userId, cardType VOCAB_RECOG|VOCAB_RECALL|KANJI_MEANING|KANJI_READING|GRAMMAR_CLOZE, refId, due, stability, difficulty, reps, lapses, lastGrade) @@unique(userId, cardType, refId) @@index(userId, due)
- **Streak**(userId @id, current, longest, lastStudyDate), **XpEvent**(userId, amount, source, day, createdAt)
- **Sentence**(id = tatoeba id, jp, en)

## 5. Japanese text rendering (the romaji / full-hiragana options)
- Every authored string is stored as `{jp, kana, romaji, segments[]}`; dictionary entries render keb + reb (+ romaji from reb).
- A `<Jp>` component + `ScriptSettingsProvider` (hydrated from the user's settings; guests fall back to localStorage) renders: **FURIGANA** = `<ruby>漢<rt>かん</rt></ruby>` per segment, **HIRAGANA** = full reading text, **ROMAJI** = `wanakana.toRomaji(kana)`. Furigana sub-mode ALWAYS/HOVER/OFF. Quick script toggle in the header + full options in `/settings`. All modes occupy similar space (layout stays stable).

## 6. Curriculum design (all levels, max detail)
- Per level: units of 3–6 lessons; each lesson = one grammar point; per unit: a vocab set (15–25 words), a kanji set (6–10), lesson practice, and a **unit exam** (15 items, pass ≥75%, unlimited shuffled retakes). A **level exam** (40 items) unlocks the next level.
- Targets: N5 12 units / ~60 grammar / 685 words / ~100 kanji · N4 14 / ~80 / 641 / ~180 · N3 16 / ~120 / 1731 / ~380 · N2 18 / ~150 / 1813 / ~400 · N1 20 / ~180 / 3428 / ~1040 (≈2,130 kanji cumulative, all jōyō).
- **Grammar lesson template (every point):** What it means (concise English) → Formation table (e.g. "Verb て-form + います") → When to use (2–4 bullets incl. politeness/register) → 3–5 examples (JP + kana + romaji + EN, using only already-taught vocab) → Common mistakes & similar-grammar comparisons → links to related lessons. The notes are written so the user has everything needed to attempt the practices.
- **Vocab injection:** unit vocab drawn from that level's JLPT list (joined by `jmdict_seq`), ordered to match lesson topics; each word gets a flashcard, 2 auto-generated quizzes (JP→EN multiple-choice recognition, EN→JP short-answer recall), and an example sentence (Tatoeba match where clean, else authored). Word detail pages: POS, all senses, TTS audio button (browser `speechSynthesis`, ja-JP — zero cost).
- **Kanji per unit:** characters chosen from that unit's vocab; card shows stroke animation, on/kun readings, meanings, example words from taught vocab, and a mnemonic; quizzes: meaning MCQ + reading MCQ.
- Content lives in typed files `content/curriculum/{n5..n1}/unitNN.ts`, zod-validated at seed; `docs/CURRICULUM.md` is the full inventory (every grammar point assigned to a unit; vocab/kanji allocation), written per level before authoring it.

## 7. Learning flow, practice, SRS
- Guided path: read lesson → practice (6–10 items, immediate feedback with explanations) → pass unit exam → next unit unlocks; `freeNav` setting unlocks everything. Forgiving by design (unlimited retries, clear progress bars) — "not too difficult, as long as there is progress".
- Practice types map to quiz-renderer's types: single (meaning), fill-blank (particles/conjugations), ordering (sentence unscramble), true-false (nuance), short-answer (conjugation drills), matching (vocab pairs), multiple (select-all usage).
- **Review:** `/review` SRS session over due cards (FSRS-lite scheduler: again/hard/good/easy → intervals 10m→1d→3d→7d→16d→35d→70d; lapses shorten). Due count surfaces on the dashboard. Cards unlock as units complete.
- **Gamification:** XP per correct item (+2 practice, +3 exam, +1 review), daily-goal ring, streaks, unit/level progress bars.

## 8. quiz-renderer compatibility (verified against its `lib/quiz-schema.ts`)
- Port quiz-renderer's **exact Zod schema** (same 7 type ids and fields; root `{title, description?, coverNotes?, feedbackMode, timeLimit?, shuffleQuestions, shuffleOptions, questions[]}`; options `{id,label}`; markdown labels). The in-app player, grading, and exports all use this one schema.
- `/quiz-exports` page: per-lesson and per-unit downloadable `QuizJson` files (e.g. "N5 Unit 3 — て-form", coverNotes = lesson notes summary; Japanese labels use parenthetical furigana like 漢字(かんじ) since quiz-renderer has no ruby support) → importable at quiz-renderer's `/quizzes/new`. Also `/api/quiz-exports/[scope]` returning the JSON. Bonus: quiz-renderer's own quiz JSONs can be pasted into our app's custom-practice importer (same schema). This stays "supplementary" — the in-app engine is primary.
